# Фарфория — Ирина Маркина

Сайт-портфолио авторских украшений: **https://markinai.ru/**.

HTML/CSS/JavaScript без сборки и небольшой CMS на Python/Flask/SQLite. Nginx отдаёт `public/`, а системная служба `markinai-cms` обслуживает `/api/` и фотографии `/uploads/` на loopback `127.0.0.1:8322`. Фильтры, просмотр украшений и подготовка обращения работают в браузере. Сообщение нужно самостоятельно скопировать и отправить Ирине; сайт не отправляет и не хранит заявки.

## Локальный просмотр

```sh
python -m venv .venv
# Windows: .venv\Scripts\python.exe вместо .venv/bin/python
.venv/bin/python -m pip install -r server/requirements.txt
.venv/bin/python server/app.py serve
```

Открыть http://localhost:8320/ и http://localhost:8320/admin/. Без `MARKINA_DATA` база хранится в игнорируемой `.cms-data/`. Для другого адреса указать `MARKINA_ORIGIN`; для другого порта также `PORT`.

Создать персональную ссылку первого входа (не выводится в журнал):

```sh
.venv/bin/python server/app.py setup-link --output /private/path/setup-link.txt
```

Открыть ссылку из файла, придумать пароль от 12 символов и войти. Ссылка одноразовая и действует 24 часа. После настройки открыть `/admin/` и использовать пароль. Для смены пароля есть раздел «Пароль и вход». Сеанс длится 8 часов; выход и смена пароля отзывают сеансы на сервере.

## Что редактируется

- Карточки: название, фото, категория, подпись, описание, публикация, подборки, видимость, порядок, добавление и удаление.
- Тексты первого экрана, галереи, блока об Ирине, образов, заказа, вопросов, контактов и подвала.
- Фотографии об Ирине и трёх образов, три фотокомпозиции первого экрана.
- Вопросы и ответы, три шага заказа, телефон и ссылки на социальные сети.

Изменения остаются в редакторе до кнопки «Сохранить на сайте». Одновременное сохранение старой вкладки отклоняется, чтобы не затереть новую версию. Можно скачать JSON копию текстов и карточек. История хранит 100 версий; восстановление сначала загружает копию в редактор и требует сохранения. Загруженные фото сохраняются отдельно, автоматически преобразуются в WebP с ограничением 2400×2400; JPEG/PNG/WebP до 12 МБ и 24 МП. Изображения не удаляются при удалении карточек, чтобы восстановление истории оставалось рабочим.

Основной сайт загружает опубликованное содержимое из `/api/content`. `public/content.json` — исходное наполнение и аварийный запас при недоступном API. Архив `/old/` остаётся статическим. Фотоистории первого экрана редактируются отдельно от карточек галереи.

Основной путь заказа: «Купить украшение» ведёт в галерею, рядом с работами показана кнопка звонка, а в открытой карточке главным действием служит «Позвонить Ирине». Подпись «Подробнее» объясняет, как открыть украшение. Подготовка письменного обращения остаётся дополнительным способом связи. Номер и его отображение в галерее, карточках и контактах берутся из общих полей админки; для звонка используется международный формат, видимый номер — `9219077253`.

На основной и архивной публичных страницах подключена Яндекс.Метрика `113832927`: `public/metrika.js` загружает предоставленный тег с Вебвизором, картой кликов, отслеживанием ссылок, точным показателем отказов и `ecommerce: "dataLayer"`. Для посетителей без JavaScript добавлен noscript пиксель. В админке счётчика нет. Поля input/textarea обращения помечены `ym-disable-keys ym-hide-content`, чтобы Вебвизор не записывал содержимое; информация о сервисе добавлена в диалог конфиденциальности. Код сам по себе не отправляет события покупок: сайт не оформляет онлайн оплату.

## Установка CMS на VPS

Из корня checkout от root:

```sh
bash deploy/install-cms.sh --http-only
# После того как оба A адреса видны в публичном DNS:
bash deploy/activate-https.sh
runuser -u markina-cms -- env MARKINA_DATA=/var/lib/markina-cms MARKINA_ORIGIN=https://markinai.ru /opt/markina-cms-venv/bin/python server/app.py setup-link --output /var/lib/markina-cms/setup-link.txt
```

Скрипт создаёт непривилегированного пользователя, venv `/opt/markina-cms-venv`, постоянную папку `/var/lib/markina-cms`, устанавливает systemd API `markinai-cms` и ежедневный снимок базы, проверяет и перечитывает Nginx только для этого сайта. До выпуска HTTPS вход в админку по HTTP закрыт. `www.markinai.ru` после активации HTTPS перенаправляется на `markinai.ru`. База, сеансы, пароль и загрузки не попадают в Git. Ссылка первого входа нужна только при пустой базе без владельца; при переносе используется существующий пароль.

Репозиторий — [WizardJIOCb/markinai.ru](https://github.com/WizardJIOCb/markinai.ru), переименованный из `WizardJIOCb/markina.ladyzenko.ru`; GitHub перенаправляет прежний адрес. Новый checkout — `/var/www/markinai.ru`; старый `/var/www/markina.ladyzenko.ru` и его vhost при установке не меняются. Обе службы используют одну постоянную базу и фотографии `/var/lib/markina-cms`, поэтому данные и пароль сохраняются, а редактирование не создаёт две расходящиеся копии. Новый API слушает только `127.0.0.1:8322`; прежняя служба `markina-cms` на `8320` остаётся для старого адреса. `deploy/markina-cms.service` — прежняя конфигурация для восстановления старого размещения.

Проверки: `systemctl is-active markinai-cms`, `curl -f https://markinai.ru/api/content`, `systemctl list-timers markina-cms-backup.timer`. Тесты: `.venv/bin/python -m unittest discover -s server -v`; они используют временную базу, а не production.

Восстановление доступа из SSH (интерактивно, пароль не передавать аргументом):

```sh
cd /var/www/markinai.ru
runuser -u markina-cms -- env MARKINA_DATA=/var/lib/markina-cms MARKINA_ORIGIN=https://markinai.ru /opt/markina-cms-venv/bin/python server/app.py reset-password
```

База ежедневно копируется SQLite backup API в `/var/lib/markina-cms/backups/`, хранятся 14 дневных снимков. Фото находятся в `/var/lib/markina-cms/uploads/`; для переноса сайта нужны база и эта папка. Копии базы на том же VPS не заменяют внешнюю резервную копию. Перед ручным восстановлением остановить обе службы `markinai-cms` и `markina-cms`, сохранить текущую базу вместе с `-wal`/`-shm`, восстановить снимок с владельцем `markina-cms`, убрать устаревшие sidecar файлы и запустить обе службы.

## Размещение

- Сервер: `82.146.42.213`.
- Git checkout: `/var/www/markinai.ru`.
- Корень Nginx: `/var/www/markinai.ru/public`.
- Конфигурация: `/etc/nginx/sites-available/markinai.ru.conf`, ссылка в `sites-enabled/`.
- HTTPS: Let's Encrypt / Certbot, webroot `public/`.

Для выпуска сертификата оба имени должны быть делегированы в `.ru` и разрешаться в `82.146.42.213` через публичный DNS. Наличие A записей только на DNS серверах регистратора ещё не подтверждает публичное делегирование. Проверка: `dig NS markinai.ru @a.dns.ripn.net +norecurse`, `dig A markinai.ru @1.1.1.1`, `dig A www.markinai.ru @1.1.1.1`.

Если делегирование ещё обновляется, можно завершить именно этот перенос одноразовой службой: установить `deploy/markinai-https-once.service` в `/etc/systemd/system/`, выполнить `systemctl daemon-reload` и `systemctl enable --now --no-block markinai-https-once.service`. Она до 24 часов проверяет оба A адреса через `1.1.1.1` и `8.8.8.8` каждые две минуты. После готовности один раз запускает выпуск сертификата и активацию HTTPS. Ошибка выпуска завершает службу без повторных ACME запросов. Успех отмечается `/var/lib/markina-cms/markinai-https.ready`, после чего служба больше не выполняется. Статус: `systemctl status markinai-https-once.service`, журнал: `journalctl -u markinai-https-once.service`. Обычное продление сертификата затем выполняет существующий Certbot timer.

При первом размещении клонировать репозиторий в указанный каталог, установить `deploy/nginx-http.conf` под именем `markinai.ru.conf`, создать ссылку в `sites-enabled`, выполнить `nginx -t` и `systemctl reload nginx`. Выпустить сертификат:

```sh
certbot certonly --webroot \
  -w /var/www/markinai.ru/public \
  -d markinai.ru -d www.markinai.ru --cert-name markinai.ru \
  --non-interactive --deploy-hook 'nginx -t && systemctl reload nginx'
```

Затем заменить конфигурацию на `deploy/nginx.conf`, повторно выполнить `nginx -t` и `systemctl reload nginx`. На сервере должен быть настроен автоматический запуск `certbot renew`.

## Обновление

### Домен синоним FARFORMER.RU

`farformer.ru` и `www.farformer.ru` перенаправляются кодом 301 на `https://markinai.ru` с сохранением пути и query параметров. Для этих двух имён используется отдельный сертификат Let's Encrypt, webroot `/var/www/markinai.ru/public`; сертификат основного домена не меняется.

Из `/var/www/markinai.ru`: `bash deploy/install-farformer.sh` устанавливает HTTP конфигурацию до выпуска сертификата и HTTPS конфигурацию после. Затем `bash deploy/activate-farformer.sh` проверяет A/AAAA через два публичных резолвера, выпускает сертификат и проверяет перенаправление. Пока DNS не готов, код выхода 75 означает, что ACME запрос не отправлялся.

Для ожидания обновления DNS установить `deploy/farformer-https-once.service` в `/etc/systemd/system/`, выполнить `systemctl daemon-reload` и `systemctl enable --now --no-block farformer-https-once.service`. Служба ждёт до 24 часов и делает одну попытку выпуска после готовности DNS; успех отмечается `/var/lib/farformer-redirect/https.ready`. Журнал: `journalctl -u farformer-https-once.service`. Действующий Nginx vhost синонима — `/etc/nginx/sites-available/farformer.ru.conf`.

После публикации изменений в `main`:

```sh
cd /var/www/markinai.ru
git status --short
git pull --ff-only origin main
```

Перед обновлением рабочий каталог должен быть чистым. Для правок только HTML/CSS/JS перезагрузка Nginx не требуется. После обновления Python перезапустить `markinai-cms`; зависимости зафиксированы в `server/requirements.txt`. Изменения конфигурации и службы применять через `bash deploy/install-cms.sh` с проверкой Nginx. Постоянное содержимое в `/var/lib/markina-cms` при обновлении не меняется.

## Версии сайта

Основная версия с анимациями находится по адресу **https://markinai.ru/**. Её HTML, CSS и JavaScript находятся непосредственно в `public/`. Предыдущий лендинг сохранён на **https://markinai.ru/old/**, исходники в `public/old/`. Общие фотографии находятся в `public/assets/`.

Адреса `/new` и `/new/` перенаправляются на главную с кодом 301. Прежние адреса ресурсов `/new/style.css`, `/new/app.js` и другие `/new/*` перенаправляются на соответствующий путь в корне. Главная открыта для индексации и имеет canonical на `/`; архивная `/old/` закрыта от индексации.

Дизайн построен по навыкам [landing-page-design](https://github.com/elayadesign/ai-design-skills/tree/main/skills/landing-page-design) и [design-to-motion](https://github.com/elayadesign/ai-design-skills/tree/main/skills/design-to-motion) из `elayadesign/ai-design-skills`, исходная ревизия `a2735a3eaf092eaaffb6dc17df25de33ef3bd048`.

Цветовая палитра, favicon и блок «Ваша история. Особенная деталь.» взяты из первой версии. На телефоне три образа можно листать горизонтально. Плашки на первом экране разделены зазором, увеличение и возврат изображений карточек выполняются плавно за 0,8 секунды.

Анимации: последовательное появление первого экрана, смена трёх фотокомпозиций с паузой и ручным выбором, появление карточек при прокрутке, проявление крупной фразы по словам, переходы в меню и карточках. Смена фотографий приостанавливается вне экрана и при скрытой вкладке; `prefers-reduced-motion` отключает движение и автопереключение. Сообщение для мастера формируется только в браузере, обязательные пожелания проверяются до подготовки текста.

Карточки, информационные диалоги и мобильное меню плавно закрываются по кнопке, Escape и, для небольших диалогов, клику снаружи. Окно остаётся модальным до завершения анимации, затем возвращаются фокус и прокрутка. При уменьшении движения закрытие происходит сразу.

Страница `public/404.html` используется для ошибок 404. Для применения маршрутов установить `deploy/nginx.conf` с проверкой `nginx -t` и последующим `systemctl reload nginx`.
